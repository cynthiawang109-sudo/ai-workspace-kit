## Problem

`taskflow-api-docs/api-conventions.md` ("Errors") requires every error
to use the top-level `{ "error": { "code", "message" } }` envelope,
with 422 for validation failures. demo-app's own errors comply, but
FastAPI's automatic request validation does not: a malformed query
parameter (e.g. `GET /v1/tasks?limit=abc`) or an invalid POST body
returns the framework default `{ "detail": [...] }` shape instead.

Recorded as a pre-existing issue in the PR #3 and PR #4 reviews
(`code-reviewer/projects/demo-app.md`) and deliberately left out of
those changes. Fix centrally with a `RequestValidationError` handler
that answers in the contract envelope (code `validation_error`),
without echoing submitted values in the message.
