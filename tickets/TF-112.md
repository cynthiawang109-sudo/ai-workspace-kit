# TF-112: Branch protection, pull request template, code owners

- Project: ai-workspace-kit (all six repos)
- Status: open
- Priority: medium

## Problem

Every repo's `main` accepts direct pushes with no required
checks: the CI built across TF-101..TF-111 (tests, lint, build,
spec conformance, docs-ci, CodeQL) is advisory only. Nothing
stops a red commit from landing on `main`, and pull requests
have no shared structure for summary, validation evidence, or
rollback.

## Change

1. **Files in all six repos** (`.github/pull_request_template.md`,
   `.github/CODEOWNERS` with `* @cynthiawang109-sudo`): one
   shared PR template whose checklist asks for the ticket link,
   validation evidence, doc/contract impact, and a rollback
   statement.
2. **Classic branch protection on `main`** in all six repos:
   - Require a pull request before merging, with **0 required
     approvals** (a solo maintainer cannot approve her own PRs;
     the gate is the PR itself plus the checks).
   - Require conversation resolution; no force pushes; no branch
     deletion.
   - Required status checks, strict (branch up to date), where a
     real gate exists:
     - demo-app: `pytest`, `lint`, `build`, `spec`,
       `Analyze (python)`.
     - taskflow-docs, taskflow-api-docs: `docs` (never
       `external-links`, which is informational by design).
     - ai-workspace-kit: `Analyze (python)` (the doc-search
       `pytest` workflow is path-filtered, so requiring it would
       block unrelated PRs forever; noted as a known limit).
     - code-reviewer, release-assistant: no CI exists, so no
       required checks - the PR requirement only.
   - **Administrators are not included in enforcement.** The
     maintainer keeps a direct-push path for the workspace's
     bookkeeping traffic (ticket files, reviewer state, docs
     sync commits, pin bumps), which is small, frequent, and
     already verified by doctor; feature work goes through PRs,
     as demo-app has since TF-101. This trade-off is deliberate
     and recorded here, not an oversight.

## Acceptance

- `GET branches/main/protection` shows the configured rules on
  all six repos, with the intended check contexts.
- A demonstration PR in demo-app (README badges) is blocked
  from merging until its required checks pass, then merges
  through the PR.
- Bookkeeping direct pushes still work after protection
  (verified with the state/pin commits that close this ticket).
- Doctor is green at the end; pins are bumped if any sub-repo
  moved.
