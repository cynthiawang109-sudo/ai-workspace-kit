# TF-115: Move the ticket system of record to GitHub Issues and a Project board

- Project: ai-workspace-kit
- Status: open
- Priority: medium

## Problem

Workspace tickets live as Markdown files in `tickets/`. That
worked while the workspace was being built, but it is a
stand-in for an issue tracker (the doc-search README says so):
no board view, no cross-references from PRs that GitHub
understands, and status lives in file text instead of in the
platform every other part of this workspace already uses -
the repos, the PR gates, the reviewer state.

## Change

1. **Migrate the history.** Every existing ticket
   (TF-101..TF-114) becomes an Issue in this repo: title keeps
   the TF id, body is the ticket text plus a footer pointing
   back to the file. All are already done, so each issue is
   closed on creation and labelled `migrated-ticket`. The
   files in `tickets/` stay as the pre-migration archive.
2. **Board.** A user-level GitHub Project for this workspace,
   linked to this repo, with a Status field (Todo /
   In progress / Done). All migrated issues are added with
   Status Done. This step needs the `project` scope on the
   maintainer's gh token (`gh auth refresh -s project`),
   which only the maintainer can grant.
3. **New work starts as an Issue.** `AGENTS.md` gains the
   rule; `list_tickets` and the doc-search README describe
   `tickets/` as the archive it now is. This ticket is the
   last one that starts as a file; on completion it is filed
   as an Issue and added to the board like the others.
4. **Draft-first is preserved.** `propose_ticket` is
   unchanged: the MCP server stays credential-free and can
   still only write local drafts. A human-run promotion
   script, `scripts/promote-draft.ps1` and `.sh`, turns a
   draft in `tickets/drafts/` into an Issue and adds it to
   the board - the same human-triggered promotion the file
   system had, one platform up. The server itself never calls
   GitHub.

## Acceptance

- 13 migrated Issues exist, closed, labelled, each linking
  its source file; the Project board lists all of them at
  Status Done (plus this ticket's own Issue at the end).
- `promote-draft` demonstrably files a throwaway draft as an
  Issue on the board; the demo issue is closed and removed
  from the board afterwards, the script and docs stay.
- AGENTS.md, WALKTHROUGH.md and the doc-search README tell
  the new story consistently (review-docs finds no
  contradiction with the archive wording).
- Doctor green at the end; pins bumped if a sub-repo moved.
